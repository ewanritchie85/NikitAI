NikitAI

$ nikitai --explain architecture

A personal assistant AI utilising an ever growing team of sub-agents, controlled by the main NikitAI orchestrator.

how a message gets routed

One entry point, a growing team

Every message goes through the same orchestrator first. A cost-effective model decides which sub-agent it belongs to. If it's not clear, NikitAI asks rather than guesses. In the web UI replies stream in as they're generated (SSE) — text appears word-by-word instead of arriving all at once — and every sub-agent answers succinctly first, expanding only when you ask for more.

Models

Routing never needs to think hard — it just picks a sub-agent — so it gets a cheap, fast model. The sub-agents do the real reasoning, and each one's model is tuned to how demanding its role is.

PurposeModelWhy
NikitAI Orchestratorclaude-haiku-4-5Cheap, fast — the task is just "which sub-agent?"
Organiserclaude-sonnet-5Turns vague instructions into polished email drafts and precise tool calls
Platform Nerdclaude-sonnet-5Real reasoning over networking principles, not just file lookup
Trainerclaude-sonnet-5Bespoke Health & fitness coaching grounded in your Garmin data
